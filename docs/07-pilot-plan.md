# 07. План пилота на реальном сайте

Цель: подтвердить, что v0.2 работает на рабочем сайте поддержки без помех операторам, и собрать данные для решений по v0.3/v1.0.

## Этап 0. Подготовка (до установки)

Собрать и передать разработчику:
- [ ] URL рабочего сайта (домен и путь к странице тикета).
- [ ] Открыт ли чат во фрейме (DevTools → есть ли `<iframe>` вокруг сообщений; если да — домен `src`).
- [ ] Как отправляется сообщение: Enter / Ctrl+Enter / только кнопка.
- [ ] На каком языке пишут операторы (для обратного перевода и `operatorLangs`).
- [ ] Бывают ли русскоязычные пользователи (тогда обязательно «Сообщение пользователя»).
- [ ] Согласование: допустимо ли отправлять тексты пользователей в Google (ПДн).
- [ ] 10–20 частых терминов продукта для глоссария (что не переводить, как переводить).
- [ ] Если есть возможность — сохранённая страница тикета (Ctrl+S, «Веб-страница полностью») с тестовыми данными: по ней подбираются селекторы без доступа к боевому сайту.

## Этап 1. Техническая проверка (тимлид + разработчик, 1 день)

1. Установить `versions/v0.2.0` в Chrome тимлида.
2. Подключить сайт (П4 в [03-processes.md](03-processes.md)), настроить все селекторы.
3. Пройти [05-testing.md](05-testing.md) на реальном тикете, в первую очередь:
   - [ ] Доступ / регистрация скриптов / обновление без F5.
   - [ ] Подписи не ломают сайт, не пропадают при прокрутке и новых сообщениях (иначе — «После сообщения»).
   - [ ] Вставка перевода в поле видна сайту (кнопка «Отправить» активна, отправляется именно перевод).
   - [ ] **Защита**: блокирует Enter и кнопку; повтор отправки после проверки и «Отправить как есть» реально отправляют сообщение (если нет — задать «Кнопка отправки»).
   - [ ] Смена тикета: язык собеседника переключается; 📌 привязывается к тикету.
   - [ ] iframe (если есть).
   - [ ] После ⟳ расширения старая вкладка не блокирует отправку.
4. Записать найденные проблемы (что делал → что ожидал → что получилось, скриншот, консоль DevTools с фильтром `SupportTranslator`).
5. Экспорт настроек → файл для пилотной группы.

## Этап 2. Пилот (2–3 оператора, 5 рабочих дней)

- День 1: установка по [04-setup-guide.md](04-setup-guide.md), 10 минут инструктажа.
- Каждый день в конце смены: «Статистика» → **Экспорт JSON** → общий чат/папка.
- Короткая форма обратной связи в конце дня:
  1. Были ли случаи, когда перевод входящего мешал или был неверным?
  2. Сколько раз правили перевод ответа вручную?
  3. Защита отправки: помогла / мешала (ложные срабатывания — примеры)?
  4. Что было неудобно?

## Метрики успеха

| Метрика | Источник | Цель |
|---|---|---|
| Доля иностранных тикетов, где оператор не открывал Google Translate вручную | Опрос | > 90% |
| Ошибки перевода | Статистика → ошибки | < 1% запросов |
| Ложные блокировки («как есть» / блокировки) | Статистика → guard | < 30% |
| Ответы, ушедшие без перевода на иностранном тикете | Выборочная проверка тимлидом | 0 |
| Поломки сайта / потерянные сообщения | Обратная связь | 0 |
| Символов в месяц (прогноз) | Статистика → стоимость | Для решения по провайдеру |

## Решения по итогам

- Какие исправления нужны → v0.2.x.
- Оставляем бесплатный Google или переходим на официальный (прогноз стоимости из статистики).
- Топ языков → для каких языков делать шаблоны ответов (v0.3).
- Нужно ли маскирование ПДн до раскатки.
- Готовность к раскатке на всю команду (v1.0).
