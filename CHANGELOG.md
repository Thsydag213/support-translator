# Changelog

## 0.3.0 — 2026-09-17 — пункты 1–6 и 9–12 из плана

### 1. Внутренние заметки не проверяются и не переводятся
- Композер хелпдеска переключается между «Reply» и «Note». В режиме заметки **защита отправки не срабатывает**, **кнопка «🌐 Перевести» скрывается**.
- Режим определяется эвристикой (`ST.isNoteMode`, `content/core.js`): от поля ввода поднимаемся к «шапке» композера и ищем видимую подпись активного режима (`Note`, `Internal note`, `Заметка`, `Внутренняя заметка`) у элемента-индикатора: кнопка-выпадашка (`aria-haspopup`/`aria-expanded`), активная вкладка (`aria-selected`, `aria-pressed`, `data-state=active`, класс `active/selected/current`).
- Новые поля правила сайта: **«Режим заметки: подписи активного режима»** (`noteModeText`, список через запятую) и **«Режим заметки: селектор»** (`noteSelector`) — явный селектор на случай, если эвристика не срабатывает.
- Кнопка перевода перепроверяет режим после любого клика (переключение Reply/Note).

### 2. Сохранение абзацев при вставке перевода
- `ST.getFieldText` для редакторов с абзацами (`<p>/<div>` на строку — ProseMirror, Draft и т.п.) собирает текст построчно; раньше `innerText` вставлял лишние пустые строки между абзацами.
- `ST.setFieldText` вставляет перевод **построчно**: `insertText` + `insertParagraph` между строками — как если бы оператор печатал и нажимал Enter; редакторы видят обычный ввод, работает Ctrl+Z. Если редактор не принял ввод — запасной вариант собирает `<p>` на каждую строку.
- Пустые строки (разрывы между абзацами) сохраняются.

### 3. Проверка чисел, сумм, валют, телефонов, ссылок и почт
- Новый модуль `lib/checks.js` → `compareFacts(оригинал, перевод)`.
- Сравниваются: числа (с нормализацией форматов: `34,99` = `34.99`, `1 234,50` = `1,234.50`, `1.234.567` = `1,234,567`), даты/время/версии по частям (`17.09.2026` = `17/09/2026` = `2026-09-17`), телефоны по цифрам (`+7 999 123-45-67` = `+7 999 123 45 67`), валюты (`USD`, `EUR`… и символы `$ € £ ₽ ₺ ¥ ₹ ₴ ₸`), ссылки, почты (без учёта регистра).
- В панели ответа: красная плашка **«🔢 Проверьте числа и ссылки. Нет в переводе: … Появилось в переводе: …»**, кнопка меняется на **«⚠ Вставить всё равно»**. Проверка повторяется при ручной правке перевода.
- Настройка: **«Сверять числа, суммы, валюты, ссылки и почты»** (`checkNumbers`, по умолчанию вкл).

### 4. Тёмная тема панелей
- Панель перевода и предупреждение защиты используют CSS-переменные темы; тёмная тема включается **автоматически по фону сайта** вокруг поля ввода (`ST.isDarkAround` — яркость первого непрозрачного фона среди предков, включая хосты shadow root).
- Настройка **«Оформление панелей расширения»** (`uiTheme`): Авто / Светлое / Тёмное.
- Подписи переводов во входящих подстроены под тёмный фон (цвета наследуются, акцент светлее).

### 5. Язык собеседника из письма во фрейме
- Когда во встроенном фрейме (HTML-письмо) переведено сообщение пользователя, фрейм сообщает язык фоновому скрипту (`convLang`), тот рассылает его остальным фреймам вкладки (`frameLang`).
- `ST.expectedLang()`: 📌 закреплённый → последнее сообщение пользователя в своём фрейме → **язык из другого фрейма** (источник `frame`, в popup — «(из письма)»). Язык из фрейма сбрасывается при смене тикета (смене URL).
- Сообщения операторов (по `userMessageSelector` или `operatorLangs`) язык не передают.

### 6. Самопроверка настроек
- Каждые 5 с (и после смены настроек) каждый фрейм оценивает своё состояние (`ST.incoming.health()`):
  - **ошибка**: окно чата найдено и в нём есть текст, но сообщения по селектору не находятся — «вероятно, сайт обновился»;
  - **предупреждение**: не выбрано «Окно чата»; поле ввода по селектору не найдено при наличии полей на странице; Google ограничил запросы; есть ошибки перевода на странице.
- Фоновый скрипт сводит состояние всех фреймов вкладки: **значок на иконке** расширения (`!` красный — ошибка, `•` оранжевый — предупреждение), текст проблем — во всплывающей подсказке иконки и списком в popup.
- Диагностика дополнена полем `health`.

### 9. Метки языка в списке тикетов
- Новое поле правила **«Превью в списке тикетов»** (`listItemSelector`) и пикер **«7. Превью в списке тикетов»**.
- Перед текстом превью ставится метка языка (`ES`, `TR`, `PT`…) для иностранных тикетов; английские и языки из «Не переводить» не помечаются.
- По умолчанию язык определяется **только встроенным детектором Chrome — без запросов в сеть**. Настройка **«Для коротких превью уточнять язык у переводчика»** (`listBadgesUseNetwork`, по умолчанию выкл) — точнее, но тратит запросы.
- Общий выключатель **«Метки языка в списке тикетов»** (`listBadges`).

### 10. Перевод темы письма
- Новое поле правила **«Тема письма/тикета»** (`subjectSelector`) и пикер **«8. Тема письма»**.
- Под темой — компактная строка `🌐 перевод` (без кнопок, подробности — во всплывающей подсказке). В статистику входящих не считается.

### 11. Вежливость обращения («ты» / «вы»)
- Google не даёт выбрать форму обращения, поэтому сделано через проверку: `informalMarkers(перевод, язык)` ищет обращение на «ты» для es, pt, de, fr, it, tr, nl, pl (`tú/puedes`, `du/dein`, `tu/t'`, `sen/sana`…).
- В панели: плашка **«🤝 Перевод обращается на «ты»: …»**. Если оригинал на русском и содержит «вы/ваш» со строчной — кнопка **«Перевести вежливо («Вы»)»**: делает «Вы/Вас/Ваш…» заглавными (подсказка переводчику на вежливую форму) и переводит заново. Если не помогло — совет поправить вручную или через глоссарий.
- Настройка **«Вежливость обращения»** (`formality`): предупреждать / не проверять.
- ⚠️ Насколько заглавное «Вы» меняет выбор Google, проверить на живом API не удалось (Google ограничил запросы с тестового IP) — сама проверка работает независимо от этого.

### 12. Подсказка опечаток
- Бесплатный провайдер запрашивает у Google проверку орфографии исходного текста (`dt=qca`); исправленный вариант возвращается в результате перевода (`spell`), учитывая метки глоссария.
- В панели: плашка **«✏️ Возможно, опечатка. Вариант: «…»»** с кнопкой **«Исправить и перевести»**.
- Настройка **«Подсказывать исправление опечаток»** (`spellCheck`). У официального Cloud API подсказок нет — плашка просто не появляется.
- ⚠️ Формат ответа Google с `dt=qca` на живом API не перепроверен по той же причине; если поле не придёт — функция молча не показывается.

### Прочее
- **Тестовый провайдер «Тестовый — без сети»** (`dev-mock`): переводит как `[es] текст`, определяет язык по ключевым словам, знает несколько опечаток — для проверки интерфейса без расхода лимитов Google. В dev-стенде: `?mock=1`.
- **Ключ кэша переводов включает провайдера** — тестовые переводы не попадают в кэш настоящего.
- **Страница «Sorry… / captcha» от Google** распознаётся как ограничение (429) — срабатывает предохранитель, а не «непонятная ошибка».
- Диагностика: темы, превью, текущий режим заметки, тёмная тема, самопроверка.
- Тестовый чат: тема письма (`#chatSubject`), переключатель **Reply / Note** (`#mode`), тёмная тема `?dark=1`; в dev-стенде `stHarness.message(...)` для эмуляции сообщений фоновой части.

## 0.2.2 — 2026-09-17 — поддержка Shadow DOM

Причина (по отчёту диагностики с реального сайта): интерфейс хелпдеска целиком рисуется внутри открытых Shadow DOM — обычный поиск элементов, наблюдение за изменениями, пикеры и стили туда не проникали; при пустых селекторах переводились служебные надписи всей страницы.

Исправлено / добавлено:
- **Shadow DOM везде**: поиск окон и сообщений, наблюдение за новыми сообщениями, поле ввода и кнопка отправки (защита), ID тикета, язык собеседника, пикеры (выбор элемента под курсором внутри shadow root), диагностика (путь с границей `>>`).
- **Стили подписей подключаются внутрь shadow root** (`content/styles.js`, constructable stylesheets); `content.css` удалён.
- **Без выбранного «Окна чата» перевод не запускается** — больше не переводится весь интерфейс сайта.
- **Пикер «6. Сообщение пользователя vs оператора»**: клик по сообщению пользователя, затем по сообщению оператора — расширение само находит отличающий класс/атрибут.
- Пикер сообщения поднимается от `<p>/<span>` к ближайшему элементу со смысловым классом; утилитарные классы (Tailwind: `flex`, `h-full`, `p-4`…) не попадают в селекторы.
- **Предохранитель лимитов Google**: при 429 или 3 неудачах подряд — пауза 60 с без запросов (или сразу резервный Cloud API, если задан ключ); плашки ошибок сами повторяют перевод после паузы.
- Наблюдение за DOM — троттлинг вместо debounce (на «живых» страницах debounce мог не срабатывать).
- Диагностика: кандидаты в поле ввода и кнопку отправки, число shadow root.
- Тестовый чат: режим `?shadow=1` (весь интерфейс в Shadow DOM).

## 0.2.1 — 2026-09-17 — первые правки после теста на реальном сайте

Исправлено:
- Встроенные фреймы без своего адреса (`about:srcdoc`, `about:blank`) — в них хелпдески показывают HTML-письма — не сопоставлялись с правилом сайта. Теперь используется адрес родительской страницы, а если селекторов окна во фрейме нет, весь документ фрейма считается одним сообщением.
- Короткие надписи интерфейса (< 40 символов), которые Chrome считает английскими, больше не отправляются в переводчик — лишние запросы на английском UI.

Добавлено:
- Popup → **🩺 Диагностика**: собирает по всем фреймам вкладки правило, найденные элементы, iframe, Shadow DOM, крупные текстовые блоки (только структура и длины, без текста переписки) и копирует отчёт в буфер.
- Тестовый чат: тикет #6 — письмо внутри `iframe srcdoc`.

## 0.2.0 — 2026-09-17 — готовность к пилоту

Добавлено:
- **Защита от отправки непереведённого текста.** Перехват Enter / Ctrl+Enter и клика по кнопке отправки. Мгновенная проверка по письменности (кириллица ↔ латиница и т.д.), для одинаковой письменности — определение языка (CLD → Google). Предупреждение: «Перевести» / «Отправить как есть» / «Отмена». Вставленный через панель перевод и короткие сообщения («ok», «спасибо») проходят без проверки.
- **Глоссарий**: термины «не переводить» и фиксированные переводы по языкам (`Кошелёк => ru: Кошелёк | es: Billetera`). Работает для входящих, исходящих и обратного перевода; проверка прямо в настройках.
- **Закрепление языка для тикета** (📌 в панели перевода). Тикет определяется по селектору ID тикета или по URL.
- **Язык собеседника только из его сообщений**: селектор «Сообщение пользователя» или список языков операторов (`operatorLangs`, по умолчанию `ru`).
- **Поддержка iframe**: скрипты работают во всех фреймах вкладки; команды popup и горячие клавиши доходят до нужного фрейма; выбор элементов работает внутри фрейма.
- **Доступ только к подключённым сайтам**: вместо `<all_urls>` — `optional_host_permissions` и динамическая регистрация скриптов. Кнопка «Подключить этот сайт» в popup, статус доступа и «Выдать доступ» у каждого правила в настройках.
- **Режим вставки «после сообщения»** — для сайтов, чей фреймворк не терпит чужих узлов внутри сообщений; автоудаление «осиротевших» подписей.
- **Статистика (из плана v0.3)**: история по дням (90 дней) — входящие/ответы по языкам, символы и запросы, кэш, ошибки, блокировки отправки. Страница статистики: плитки, график по дням, языки, оценка стоимости официального API, таблица, экспорт JSON/CSV, объединение файлов коллег для командных цифр.
- Popup: подключение сайта, статус по всем фреймам (язык собеседника, 📌, защита), пикеры «Кнопка отправки» и «ID тикета», ссылка на статистику.
- Настройки: новые поля правил, языки операторов, порог защиты, глоссарий, Ctrl+S, предупреждение о несохранённых изменениях.
- После обновления расширения старые скрипты на открытых вкладках сразу отключаются и просят обновить страницу.
- Тестовые страницы: `mock-iframe.html` (чат во фрейме с другого origin), `stats-preview.html` (статистика на демо-данных).

Изменено:
- Статистика хранится в `statsDays` (старый ключ `stats` 0.1.0 удаляется при обновлении).
- Кэш перевода учитывает версию глоссария.
- Тост после вставки перевода — вверху экрана (не перекрывает поле ввода).

Миграция с 0.1.0:
- После обновления расширение **не работает ни на одном сайте, пока не выдан доступ**: popup → «Подключить этот сайт» или настройки → «Выдать доступ» у правила.

## 0.1.0 — 2026-09-17 — прототип
