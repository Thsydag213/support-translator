# Changelog

## 0.7.1 — 2026-09-26 — китайский, ручное скачивание пакетов и моделей, флажки в настройках

### Китайский — язык платформы
- Упрощённый китайский (`zh-CN`) добавлен в языки ответов по умолчанию. У кого список уже сохранён — добавится один раз автоматически.
- **Почему перевод на китайский «не работал»:** пакетов встроенного переводчика для китайского не было (скачиваются только по клику), а бесплатный Google в тот момент ограничивал запросы — перевод падал с ошибкой. Теперь в панели ответа при такой ошибке есть кнопка **«⬇ Скачать пакет ru→zh»**: пакет скачивается прямо отсюда, и перевод повторяется на устройстве.
- Упрощённый и традиционный китайский для ответов теперь разные языки: галочка «Китайский (Китай)» больше не включает заодно `zh-TW`. Если клиент пишет на традиционном, а включён только упрощённый — ответ на упрощённом (а не на английском).
- Тема обращения понимает китайский (упрощённый и традиционный): 退款, 取消, 扣款, 登录, 错误, 删除账户, 订阅, 谢谢.
- Сверка чисел понимает валюту словом: «69,70 евро» = «69.70欧元» = «€69.70» = «10ドル» = «10유로» = «10 يورو» и т.д. (евро, доллар, фунт, рубль, иена, гривна, лира на 10+ языках). Раньше на китайском, японском, корейском и арабском переводе проверка ложно ругалась на «€»/«$». Реальные расхождения (другая сумма, другая валюта) ловятся как раньше.
- Проверено на тестовом чате: входящее на китайском переведено, язык ответа — китайский, подсказка о смене языка, тема «Возврат денег»; перевод ответа на китайский через Google; ошибка «нет пакета + Google ограничил» → кнопка скачивания → перевод на устройстве.

### Ручное скачивание пакетов и моделей
- Настройки → «Перевод на устройстве» → **«Проверить пакеты»**: список всех нужных пар (языки собеседников и языки ответов ↔ английский и языки операторов) со статусом — скачан / нужно скачать / скачивается / не поддерживается / браузер не ответил. **У каждой пары своя кнопка «Скачать»** с прогрессом в процентах; недостающие — сверху. «Скачать все недостающие» качает только то, чего нет.
- Проверка идёт по 3 пары одновременно: на десятки параллельных запросов Chrome мог не отвечать, и раньше всё показывалось как «нет ответа». Если браузер не ответил — статус «?» и кнопка «Скачать» всё равно доступна.
- **Модели на устройстве** — отдельный блок: определение языка, языковая модель (Gemini Nano, ~2 ГБ — для «Исправить / Вежливее / Короче» и «Кратко о тикете»), Summarizer. Статус и кнопка «Скачать» с прогрессом, не дожидаясь первого использования.

### Настройки
- Флажки было не видно: общий стиль полей (отступы, `min-width: 0`) сжимал их в точку рядом с длинным текстом. Теперь флажок 16×16, текст выровнен по верху, список «Помощник агента» — в одну колонку.


## 0.7.0 — 2026-09-26 — помощник агента

Тринадцать функций для скорости, качества и приватности. Все включаются и выключаются в настройках → «Помощник агента».

### Скорость
- **⚡ Быстрая вставка** (`quickInsert`): перевести и сразу вставить без панели. Shift+клик по кнопке — другой режим. Безопасность: если числа/суммы/ссылки не совпали или перевод обращается на «ты», вместо вставки открывается панель; если текст в поле изменился во время перевода — ничего не вставляется. Подсказка «↩ Вернуть и открыть панель». Отдельная команда «Перевести ответ и сразу вставить» для своего сочетания клавиш.
- **🧠 Память переводов** (`tmEnabled`, `content/tm.js`): при вставке через панель пара «ваш текст → перевод, который вы подтвердили и, возможно, поправили» запоминается (до 3000 записей, локально). Тот же текст на тот же язык переводится мгновенно — с вашими правками, без запроса. В панели пометка и «Перевести заново»; выгрузка в JSON и очистка в настройках.
- **⋯ Палитра команд** (`content/palette.js`): кнопка «⋯» у поля ввода, «Все команды» в меню расширения или своё сочетание клавиш. Перевод, быстрая вставка, правка моделью, кратко о тикете, закрепить язык ответа или снять закрепление, перевести окно заново, скопировать диагностику, настройки, сочетания клавиш, тур. Поиск, ↑↓, Enter, Esc.

### Качество ответа
- **✨ Локальная модель Chrome** (`assist`, `content/assist.js`): в панели ответа кнопки «Исправить / Вежливее / Короче / Проще». Модель (Prompt API, на устройстве) работает с английским: текст → английский → правка → язык клиента. Модели велено не менять факты, ссылки, числа и метки, а проверки панели всё равно сверяют числа и ссылки с оригиналом. Пометка «отредактировано моделью» и кнопка «Обычный перевод». Если в скрипте сайта API нет — через страницу расширения (offscreen).
- **🧠 Кратко о тикете**: что хочет клиент, пересказ с ключевыми фактами, настроение, тема, языки, число сообщений. Модель получает переписку в английском переводе. Без модели — Summarizer API, без него — первые фразы последних сообщений клиента. Копирование, обновление.
- **🏷 Тема обращения** — по ключевым словам на 12 языках (возврат, отмена, списание, вход, техническая проблема, удаление аккаунта, подписка, благодарность), мгновенно и без модели. Показывается у поля ввода (клик — «Кратко о тикете»). Подсказка макросов по теме из настройки `intentMacros` (`refund: ref recur 3m, ref ups`); клик по макросу копирует название для поиска.
- **🔀 Смена языка посреди диалога** (`langChangeNotice`): если последнее сообщение клиента на другом языке, чем предыдущее, — подсказка «Клиент перешёл с испанского на французский. Ответ будет на: …»; при закреплённом другом языке — кнопка «Снять 📌». Один раз на тикет и пару языков.
- **Арабский и другие RTL-языки**: поле перевода в панели переключается на письмо справа налево, переводы входящих — `dir=auto`.

### Надёжность
- **🔧 Самопроверка селекторов** (`selectorCheck`): дополнительно проверяются «Кнопка отправки» и «Сообщение пользователя». Если проблема держится ~15 с (не мигание при смене тикета) — предупреждение прямо на странице с кнопкой «Настройки», один раз за сессию.
- **⬆ Проверка обновлений** (`updateCheck`): раз в 12 часов версия сверяется с `extension/manifest.json` на GitHub (`raw.githubusercontent.com` — единственный новый адрес в разрешениях). Напоминание на странице один раз для каждой версии и плашка в меню расширения со ссылкой на архив.
- **💶 Лимит Google Cloud** (`cloudMonthlyLimit`, `cloudStopAtLimit`): расход за календарный месяц — в меню расширения и настройках (жёлтый с 80%, красный с 100%). При исчерпании лимита Cloud не используется до 1-го числа, чтобы не было счёта (отключаемо).

### Приватность
- **🔒 Персональные данные не уходят в облако** (`maskPii`, `lib/pii.js`): почты, номера карт, IBAN, телефоны и номера заказов/транзакций заменяются метками `⟦p0⟧` перед отправкой облачному переводчику и возвращаются в перевод. Суммы, даты и проценты не трогаются. Если переводчик потерял метку — перевод повторяется без маскирования, данные не пропадают. Перевод на устройстве не маскируется — текст никуда не уходит.

### Знакомство с расширением
- **🎓 Тур** (`onboarding/`): страница из 7 шагов открывается при установке и один раз при обновлении до 0.7; потом — «Как пользоваться» в меню расширения и в палитре.

### Прочее
- Диагностика: блок `helper` (включённые функции, тема тикета, есть ли API модели на странице), `maskPii`, `cloudUsage`. Текста сообщений в отчёте по-прежнему нет.
- Тестовый стенд: `?fakellm=1` — эмуляция локальной модели.
- Сочетания клавиш в меню расширения читаются через промис (работает и в Firefox/Safari).

Проверено на тестовом чате (эмуляция встроенного переводчика и модели):
- маскирование: провайдер получил `Mi correo es ⟦p0⟧, tarjeta ⟦p1⟧, tel ⟦p2⟧ y pedido ⟦p3⟧`, в переводе данные восстановлены; при потере меток — повторный запрос без маскирования; суммы, даты, проценты не маскируются;
- память переводов: поправленный вручную перевод вставлен, при повторе того же текста подставлен из памяти с пометкой;
- RTL: при выборе арабского поле перевода `dir=rtl`;
- правка моделью: русский → английский → «вежливее» → испанский, пометка в панели;
- быстрая вставка: обычный текст вставлен сразу и распознаётся защитой как перевод; при несовпадении суммы открылась панель, поле не изменено;
- тема обращения у кнопки и в «Кратко о тикете» (с моделью и без неё), подсказка макросов;
- палитра: 21 команда, поиск «отвечать фр» → закрепление французского по Enter;
- смена языка: новое сообщение клиента на французском после испанских — подсказка, язык ответа — французский;
- самопроверка: неверный селектор кнопки отправки — предупреждение через ~15 с;
- обновления: адрес на GitHub отвечает, напоминание о новой версии показывается один раз;
- настройки: новый раздел сохраняется и читается, расход Cloud показан;
- регрессия: входящие переводятся, Enter не перехватывается, Ctrl+Enter с русским текстом в испанском тикете — предупреждение; синтаксис всех скриптов проверен.


## 0.6.0 — 2026-09-25 — другие браузеры и «Отправить и закрыть»

### Firefox, Safari, Edge
- **Слой совместимости** `lib/compat.js` (подключается первым везде): в Firefox и Safari `chrome.*` работает через колбэки, а весь код написан на промисах — теперь `chrome` подменяется на `browser`. В `ST_ENV` — браузер и доступные возможности (offscreen, встроенный переводчик).
- **Сборка для Firefox**: `tools/build-firefox.ps1` → `dist/firefox-v*` и zip. В манифесте фоновый скрипт вместо service worker, `browser_specific_settings` (Gecko), убраны `offscreen` и `minimum_chrome_version`.
- Регистрация content scripts не падает в Firefox: `matchOriginAsFallback` (письма во фреймах `about:srcdoc`) пробуется отдельно, при отказе регистрация повторяется без него.
- **Edge** — работает той же папкой, что и Chrome, включая перевод на устройстве.
- **Safari** — та же папка после `xcrun safari-web-extension-converter`.
- Перевод на устройстве (Translator API) есть только в Chrome и Edge; в Firefox и Safari перевод идёт через облако, в настройках об этом написано прямо. Остальное — входящие, панель перевода, защита отправки, проверки, глоссарий, статистика, диагностика — работает одинаково.
- В диагностику добавлен браузер и наличие offscreen; README и руководство по установке дополнены разделом про браузеры.

### Защита отправки и «Отправить и закрыть»
- Раньше проверялась только кнопка из правила сайта, поэтому отправка из меню у кнопки («Send and close», «Отправить и отложить») проходила без проверки.
- Теперь такие пункты меню узнаются по подписи (`send`, `reply`, `submit`, `отправить`, `ответ` в `data-testid`, `aria-label`, `title` или тексте) и тоже проверяются. Стрелка, которая только открывает меню (`aria-haspopup` / `aria-expanded`), не перехватывается — меню открывается как обычно.
- Пункт меню расширение само не нажимает (меню уже закрыто, а обычная кнопка отправки сделала бы не то): после проверки появляется подсказка «✔ Язык проверен — выберите действие отправки ещё раз», и повторный выбор проходит без проверки.

Проверено на тестовом чате: «Send and close» с русским текстом в испанском тикете — предупреждение, сайт клик не получил; после «Отправить как есть» повторный выбор дошёл до сайта; «Snooze» и стрелка меню не перехватываются; обычная кнопка отправки работает как раньше; страница с `browser.*` вместо `chrome.*` — слой совместимости подменяет объект; манифест Firefox собирается и разбирается без ошибок; входящие, панель перевода и список языков ответов не изменились.


## 0.5.7 — 2026-09-17 — ссылки в ответе не теряются при переводе

Проблема: ссылки, вложенные в текст ответа («here» со ссылкой на страницу), после перевода превращались в обычное слово — адрес пропадал.

Причина: для перевода из поля ввода бралась только видимая часть текста, адрес ссылки в неё не попадал.

Исправлено:
- Ссылка, у которой текст отличается от адреса, читается как **«текст (адрес)»**: `here (https://example.com/terms)`. Адрес проходит через перевод без изменений и после вставки стоит рядом с переведённым словом обычной ссылкой (сайт сам делает её кликабельной).
- Ссылки, где текст и есть адрес (`example.com`), не дублируются. Для `mailto:` / `tel:` в скобках — сам адрес почты или телефон.
- Проверка «числа и ссылки» сверяет адрес в переводе с оригиналом — если переводчик его испортит, будет предупреждение.
- Работает вместе с сохранением картинок, абзацев и списков.

Проверено на тестовом чате: поле со ссылкой «здесь», ссылкой-адресом, картинкой и ссылкой mailto — адреса в переводе и в поле после вставки, картинка на месте.


## 0.5.6 — 2026-09-17 — Enter снова выбирает макросы и переносит строку

Проблема: после 0.5.4 Enter всё равно перехватывался — нельзя было выбрать макрос из списка по Enter и сделать перенос строки.

Причина: режим «Авто» пытался сам заметить, что сайт отправляет по Enter (поле опустело после Enter). Но выбор макроса по Enter тоже на мгновение очищает поле (`#3` удаляется перед вставкой макроса) — расширение ошибочно запомнило «сайт отправляет по Enter» и стало проверять каждый Enter.

Исправлено:
- Автоопределение отправки по Enter **удалено**; ошибочно запомненное значение стирается при загрузке. В режиме «Авто» обычный Enter не проверяется никогда — проверяются только Ctrl/⌘+Enter и кнопка отправки.
- **Открытый выпадающий список у поля** (макросы, упоминания, подсказки: `role="listbox"`/`menu`, tippy/radix/popover — всплывающий слой рядом с полем ввода, пересекающийся с ним по горизонтали) — Enter и Ctrl+Enter не перехватываются, т.к. выбирают пункт списка. То же у поля с `aria-expanded="true"` / `aria-activedescendant`. Постоянные панели страницы (список разговоров) не учитываются.
- Диагностика: причина «открыт выпадающий список у поля (макросы/подсказки)»; поле `enterLearned` убрано.

Проверено: обычный Enter не перехватывается; Ctrl+Enter при открытом списке макросов не перехватывается; после закрытия списка Ctrl+Enter с русским текстом в испанском тикете — предупреждение; высокий список слева от поля (как список разговоров) на проверку не влияет.


## 0.5.5 — 2026-09-17 — перевод между любыми языками без Google (через английский)

Проблема: перевод ответа с испанского на корейский падал с ошибкой «Google временно ограничил запросы», хотя пакеты встроенного переводчика скачаны. В других тикетах всё работало.

Причина (отчёт диагностики: `missingPacks: ["es>ko"]`): кнопка «Скачать языковые пакеты» скачивает пары «язык ↔ английский/русский». Прямой пары испанский → корейский нет, поэтому перевод уходил в Google, а он был ограничен.

Исправлено:
- **Перевод через английский на устройстве**: если прямого пакета нет, а пакеты «исходный → английский» и «английский → целевой» скачаны, текст переводится в два шага (es → en → ko) без Google. Абзацы, списки и глоссарий сохраняются так же.
- Кнопка «Скачать языковые пакеты» теперь всегда включает английский как опорный язык и все включённые «Языки ответов» (в обе стороны).
- Понятная ошибка, если не хватает пакета и облако недоступно: «Нет скачанного языкового пакета es→ko (или пар через английский), а облако не ответило: … Скачайте пакеты: настройки расширения → «Перевод на устройстве» → «Скачать языковые пакеты».»

Проверено на эмуляции встроенного переводчика: португальский → испанский без прямого пакета переведён через английский (абзацы и маркер списка на месте); для пары без пакетов — новое сообщение с подсказкой.


## 0.5.4 — 2026-09-17 — Enter снова переносит строку

Проблема: на сайте, где Enter переносит строку, а отправка — Ctrl+Enter, защита перехватывала обычный Enter и не давала сделать отступ.

Причина: в правиле сайта осталось значение по умолчанию «Отправка с клавиатуры: Enter» — защита блокировала каждый Enter в поле с непереведённым текстом.

Исправлено:
- Новый режим **«Авто»** (по умолчанию): проверяются Ctrl/⌘+Enter и кнопка отправки. Обычный Enter **не блокируется никогда**; расширение само замечает, отправляет ли сайт по Enter (после Enter поле опустело) — только тогда Enter тоже начинает проверяться. Если Enter переносит строку, режим не меняется.
- Все правила со значением «Enter» один раз автоматически переводятся на «Авто». Явно выбрать «Enter», «Ctrl+Enter», «Shift+Enter» или «Только кнопкой» по-прежнему можно — выбор после обновления сохраняется.
- Диагностика: `guard.sendKey` и `guard.enterLearned` (заметило ли расширение отправку по Enter).
- Тестовый чат: `?ctrlsend=1` — Enter переносит строку, отправка по Ctrl+Enter.

## 0.5.1 — 2026-09-17 — кнопка отправки работает, письма пользователей снова переводятся

### Кнопка отправки «не отправляла»
Причины:
- «Кнопка отправки» в правиле указывала на обёртку с несколькими кнопками (отправка, эмодзи, вложения). Защита отправки перехватывала клик, проверяла язык и повторяла отправку программным кликом по обёртке — сайт такой клик игнорирует.

- **Проверка языка заранее**: пока оператор печатает (пауза 0,5 с), язык текста проверяется без облака (CLD и встроенный детектор). Если язык совпадает с языком ответа — клик/Enter не перехватывается, сайт получает настоящее нажатие.

- Повторная отправка кликает по **реально нажатой кнопке** (с pointer/mouse-событиями), а не по обёртке.

- Вставленный перевод узнаётся без учёта переносов строк и пробелов.
- Пикер «Кнопка отправки»: при клике мимо кнопки берёт единственную кнопку внутри; предпочитает короткий селектор по `data-testid` (например `button[data-testid="send-button"]`); id, сгенерированные фреймворком (`base-ui-_r_fb_`, `:r1:`, `radix-…`), больше не попадают в селекторы.

- **Мост через страницу расширения**: если на странице сайта Translator API недоступен или не отвечает, перевод и определение языка выполняются на скрытой странице расширения (offscreen document, новое разрешение `offscreen`), где API доступен. - **Защита отправки** определяет язык текста сначала без облака; если облако недоступно — использует догадку, а не показывает «другой язык».
- **Скачивание пакетов в обе стороны**: для каждого языка собеседника — пары с языком перевода входящих, языками операторов и языком обратного перевода, в обе стороны (например, es→en, en→es, es→ru, ru→es).
- Таймауты встроенного переводчика увеличены (проверка 5 с, создание 15 с, перевод 20 с); отключение API на странице — после 5 зависаний (дальше работает мост).

Проверено на dev-стенде (эмуляция встроенного переводчика, все запросы к Google возвращают 429):
- входящие испанские: уверенный язык — на устройстве; неуверенный — одна попытка облака (сразу отказ) и перевод на устройстве по догадке;
- панель ответа, русский текст: «С: Русский», перевод ru→es и обратный es→ru на устройстве, **0 запросов к Google**;
- панель ответа, английский текст (как на скриншоте): перевод en→es на устройстве.
Не проверено вживую: мост через offscreen document в установленном расширении.

## 0.4.0 — 2026-09-17 — меньше запросов к Google, перевод на устройстве, резерв Google Cloud

Причина: бесплатный Google несколько раз за день ограничивал IP (перенаправление на страницу проверки) даже при ~170 запросах.

### 1. Меньше запросов
- **Перевод только видимых сообщений** (`onlyVisible`, по умолчанию вкл). Сообщение переводится, когда оно на экране или рядом (±600px) — через IntersectionObserver (работает и в Shadow DOM). История тикета выше экрана не переводится, пока до неё не долистали. Проверено: из 43 сообщений переведены только видимые 3, после прокрутки вниз — ещё 4 появившихся.
- **Объединение запросов** (`batchRequests`, по умолчанию вкл). Сообщения одного языка (по встроенному детектору Chrome), пришедшие в течение 150 мс, уходят одним запросом (до 20 сообщений / 3500 символов):
  - бесплатный Google — тексты склеиваются через метки `⟦900001⟧`; если после перевода частей не столько же — сообщения автоматически переводятся по одному;
  - Google Cloud — нативный массив `q`, язык определяется для каждого текста.
  - Проверено на подменённом ответе: 3 сообщения → 1 запрос; при «съеденных» разделителях — корректный перевод по одному.
- **Постоянный кэш переводов** в `storage.local` (раньше — до перезапуска браузера): до 3000 записей, срок 30 дней, старые удаляются автоматически. Повторно открытые тикеты не переводятся заново. «Очистить кэш» чистит и его.
- Статистика: «переведено на устройстве», «сообщений объединено».

### 2. Перевод на устройстве (встроенный переводчик Chrome)
- Новый модуль `content/local-translator.js` — Translator API и Language Detector API (Chrome 138+): перевод прямо в браузере, **без сети, без лимитов, тексты не уходят в Google**.
- Настройка **«Перевод на устройстве»** (`localTranslator`): для входящих и обратного перевода (по умолчанию) / только входящие / не использовать. Перевод ответа пользователю всегда идёт в облаке (качество важнее).
- Язык источника: встроенный детектор Chrome (CLD), если уверен; иначе Language Detector API (уверенность ≥ 0,7). Без уверенного языка — облако.
- Используются только **уже скачанные** языковые пакеты (скачивание требует клика). Настройки → «Перевод на устройстве» → **«Проверить пакеты»** / **«Скачать языковые пакеты»** для списка языков собеседников.
- Глоссарий работает: если метки терминов не пережили перевод на устройстве — сообщение переводится в облаке.
- **Защита от зависания API**: таймауты (проверка пакета 3 с, создание 10 с, перевод 15 с) → облако; после 3 зависаний встроенный переводчик отключается до перезагрузки страницы. Проверено: при не отвечающем API сообщение переведено облаком за 3,3 с.
- Подпись перевода показывает источник: «на устройстве (Chrome)», «Google», «Google Cloud».
- Диагностика: `found.localTranslator` (наличие API, недостающие пакеты), `onlyVisible`.

### 3. Резерв Google Cloud
- При ограничении/недоступности бесплатного Google (в т.ч. во время паузы предохранителя) запросы **сразу идут в Google Cloud** — и одиночные, и объединённые. Проверено на подменённых ответах: бесплатный 429 → оба сообщения в Cloud одним запросом; следующий запрос во время паузы — сразу в Cloud, бесплатный не запрашивается.

## 0.3.1 — 2026-09-17 — по итогам теста на реальном хелпдеске

### Сообщения агентов — перевод по кнопке
- Новое поле правила **«Сообщения агентов»** (`agentMessages`): **по кнопке** (по умолчанию) / автоматически / не переводить.
- Агент = сообщение, которое не попадает под «Сообщение пользователя» (`userMessageSelector`). Без этого селектора все сообщения считаются сообщениями пользователя (как раньше).
- В режиме «по кнопке» у сообщения агента — маленькая кнопка **«🌐 перевести»**; запрос к переводчику уходит только после клика. Английские сообщения (по встроенному детектору Chrome) кнопку не получают.
- Запрошенный перевод держится при обновлениях ленты (запоминается по хэшу текста); если текст сообщения изменился — снова кнопка.
- Переводы сообщений агентов не считаются во «входящих» статистики и не влияют на язык собеседника.
- Диагностика: `messageBreakdown` (всего / пользователь / агент), `agentButtons`.

### Пикер «Пользователь vs оператор» понимает «сторону» сообщения
- Если части переписки одинаковые, а сообщения агента отличаются классом выравнивания (`justify-end`, `self-end`, `ml-auto`, `out`…), пикер строит селектор вида **`[общий признак]:not(.класс-стороны)`** — он охватывает и письма, и чат-сообщения пользователя. Проверено на разметке, повторяющей реальный хелпдеск: получен `[data-testid^="conversation-part-id-"]:not(.justify-end)`.
- Атрибуты с номером в конце (`conversation-part-id-464826615`) превращаются в «начинается с» (`[data-testid^="conversation-part-id-"]`) — во всех пикерах.

### «Окно чата» слишком общее
- Причина: пикер строил путь из безликих `div > div > …` (783 совпадения) — тяжёлый обход и дубли сообщений (36 вместо 2).
- Пикер «1. Окно чата» теперь сначала ищет смыслового предка (id, класс, `data-testid`, `role`, `aria-label`), совпадающего не более чем с 3 элементами.
- Если окно всё же совпало больше чем с 30 элементами — сообщения ищутся одним проходом по странице, а самопроверка показывает предупреждение «Окно чата выбрано слишком общо».
- Найденные сообщения без дублей; при вложенных совпадениях берётся самый внутренний элемент.

### Режим заметки — без ложных срабатываний
- В отчёте был `noteModeNow: true` при режиме Email — защита отправки фактически не работала.
- Подпись режима считается активной, только если: выбранная вкладка/переключатель (`aria-selected/pressed/checked=true`, `data-state=active`, класс `active/selected` — у самого элемента или прямого родителя), **или** это кнопка-выпадашка (`aria-haspopup`), на которой написан режим. Пункты меню (`role=menu/menuitem/option`) и обычные кнопки «Note» больше не считаются.
- Диагностика: `noteModeReason` — какой элемент и почему решил, что это заметка.

### Ошибка в «Расширения → Ошибки» (CORS, google.com/sorry)
- Когда Google ограничивает IP, он перенаправляет запрос на страницу проверки `google.com/sorry`; fetch шёл по редиректу и Chrome записывал CORS-ошибку в ошибки расширения, а запрос повторялся 3 раза.
- Теперь `redirect: 'manual'`: перенаправление распознаётся сразу как ограничение (429) → пауза предохранителя, без повторов и без записи CORS-ошибки.
- Проверка орфографии (`dt=qca`) запрашивается **только для текста оператора** в панели ответа (входящие — только перевод): меньше «тяжёлых» запросов; ключ кэша учитывает этот флаг.

### Прочее
- Текст сообщения больше не включает служебные элементы: кнопки (`Reply to this message`), `role=button`, `aria-hidden`, SVG.
- Крошечные служебные фреймы (виджет мессенджера 1×1, кнопка 48×48) не обрабатываются и не участвуют в самопроверке.
- Смена «Сообщение пользователя» или «Сообщения агентов» в настройках сразу перестраивает переводы.

## 0.2.2 — 2026-09-17 — поддержка Shadow DOM

Причина (по отчёту диагностики с реального сайта): интерфейс хелпдеска целиком рисуется внутри открытых Shadow DOM — обычный поиск элементов, наблюдение за изменениями, пикеры и стили туда не проникали; при пустых селекторах переводились служебные надписи всей страницы.

Исправлено / добавлено:
- **Shadow DOM везде**: поиск окон и сообщений, наблюдение за новыми сообщениями, поле ввода и кнопка отправки (защита), ID тикета, язык собеседника, пикеры (выбор элемента под курсором внутри shadow root), диагностика (путь с границей `>>`).
- **Стили подписей подключаются внутрь shadow root** (`content/styles.js`, constructable stylesheets); `content.css` удалён.
- **Без выбранного «Окна чата» перевод не запускается** — больше не переводится весь интерфейс сайта.
- **Пикер «6. Сообщение пользователя vs оператора»**: клик по сообщению пользователя, затем по сообщению оператора — расширение само находит отличающий класс/атрибут.
- Пикер сообщения поднимается от `<p>/<span>` к ближайшему элементу со смысловым классом; утилитарные классы (Tailwind: `flex`, `h-full`, `p-4`…) не попадают в селекторы.
- **Предохранитель лимитов Google**: при 429 или 3 неудачах подряд — пауза 60 с без запросов (или сразу резервный Cloud API, если задан ключ); плашки ошибок сами повторяют перевод после паузы.
- Наблюдение за DOM — троттлинг вместо debounce (на «живых» страницах debounce мог не срабатывать).
- Диагностика: кандидаты в поле ввода и кнопку отправки, число shadow root.
- Тестовый чат: режим `?shadow=1` (весь интерфейс в Shadow DOM).

## 0.2.1 — 2026-09-17 — первые правки после теста на реальном сайте

Исправлено:
- Встроенные фреймы без своего адреса (`about:srcdoc`, `about:blank`) — в них хелпдески показывают HTML-письма — не сопоставлялись с правилом сайта. Теперь используется адрес родительской страницы, а если селекторов окна во фрейме нет, весь документ фрейма считается одним сообщением.

## 0.2.0 — 2026-09-17 — готовность к пилоту

Добавлено:
- **Защита от отправки непереведённого текста.** Перехват Enter / Ctrl+Enter и клика по кнопке отправки. Мгновенная проверка по письменности (кириллица ↔ латиница и т.д.), для одинаковой письменности — определение языка (CLD → Google). Предупреждение: «Перевести» / «Отправить как есть» / «Отмена». Вставленный через панель перевод и короткие сообщения («ok», «спасибо») проходят без проверки.
- **Глоссарий**: термины «не переводить» и фиксированные переводы по языкам (`Кошелёк => ru: Кошелёк | es: Billetera`). Работает для входящих, исходящих и обратного перевода; проверка прямо в настройках.
- **Закрепление языка для тикета** (📌 в панели перевода). Тикет определяется по селектору ID тикета или по URL.
- **Язык собеседника только из его сообщений**: селектор «Сообщение пользователя» или список языков операторов (`operatorLangs`, по умолчанию `ru`).
- **Поддержка iframe**: скрипты работают во всех фреймах вкладки; команды popup и горячие клавиши доходят до нужного фрейма; выбор элементов работает внутри фрейма.
- **Доступ только к подключённым сайтам**: вместо `<all_urls>` — `optional_host_permissions` и динамическая регистрация скриптов. Кнопка «Подключить этот сайт» в popup, статус доступа и «Выдать доступ» у каждого правила в настройках.
- **Режим вставки «после сообщения»** — для сайтов, чей фреймворк не терпит чужих узлов внутри сообщений; автоудаление «осиротевших» подписей.
- **Статистика (из плана v0.3)**: история по дням (90 дней) — входящие/ответы по языкам, символы и запросы, кэш, ошибки, блокировки отправки. Страница статистики: плитки, график по дням, языки, оценка стоимости официального API, таблица, экспорт JSON/CSV, объединение файлов коллег для командных цифр.
- Popup: подключение сайта, статус по всем фреймам (язык собеседника, 📌, защита), пикеры «Кнопка отправки» и «ID тикета», ссылка на статистику.
- Настройки: новые поля правил, языки операторов, порог защиты, глоссарий, Ctrl+S, предупреждение о несохранённых изменениях.
- После обновления расширения старые скрипты на открытых вкладках сразу отключаются и просят обновить страницу.
- Тестовые страницы: `mock-iframe.html` (чат во фрейме с другого origin), `stats-preview.html` (статистика на демо-данных).

Изменено:
- Статистика хранится в `statsDays` (старый ключ `stats` 0.1.0 удаляется при обновлении).
- Кэш перевода учитывает версию глоссария.
- Тост после вставки перевода — вверху экрана (не перекрывает поле ввода).

Миграция с 0.1.0:
- После обновления расширение **не работает ни на одном сайте, пока не выдан доступ**: popup → «Подключить этот сайт» или настройки → «Выдать доступ» у правила.
